2. RECOMMENDED CURSOR SETTINGS [analyst]
==========================================================================
  Settings path [Linux]: ~/.config/Cursor/User/settings.json
  Settings path [Windows]: %APPDATA%\Cursor\User\settings.json
  Settings path [macOS]: ~/Library/Application Support/Cursor/User/settings.json

  Open: Cursor menu -> Settings -> open settings.json [or search setting
  name in Settings UI and edit there].

  Suggested for this kit [paste into settings.json; merge with existing]:

    "files.autoSave": "afterDelay",
    "files.autoSaveDelay": 1000,
    "editor.wordWrap": "on",
    "editor.rulers": [108],
    "editor.renderWhitespace": "boundary",
    "editor.minimap.enabled": false,
    "editor.largeFileOptimizations": true,
    "files.watcherExclude": {
      "**/.git/objects/**": true,
      "**/.git/subtree-cache/**": true
    },
    "search.exclude": {
      "**/node_modules": true
    }

  Cursor / Agent [Settings -> Cursor Settings or Features]:
    - Enable project rules [.cursor/rules] -- should be on by default.
    - Agent mode: use for put in / promote / multi-step kit edits.
    - Ask mode: use for read-only explain, map, draft in chat.
    - Model: pick one you trust for long context; kit chats work best
      when you start fresh per task [see section 7].
    - Privacy: review what you send if cases contain personal notes.

  Optional quality-of-life:
    - Pin cf_grep.txt and wip.txt in editor tabs for session orient.
    - Terminal: integrated bash [default on Linux / Steam Deck].
    - Git: enable if you version the kit; agents will not commit unless
      you explicitly ask.

  Not recommended for this project:
    - Letting agents cat entire theory/applied/cases files [hooks nudge
      against this; wastes context].
    - Auto-format on save for kit txt [108-char convention is manual].

4. SESSION START [you -- 30 seconds]
==========================================================================
  Run in terminal from project root:

    sed -n '/^WIP STATUS INDEX/,/^ACTIONABLE QUEUE/p' coherence_framework_v25_wip.txt
    sed -n '/^ACTIONABLE QUEUE/,/^CLOSED LOG/p' coherence_framework_v25_wip.txt | head -20

  Or read cf_grep.txt SESSION ORIENT block [lines ~50-55].

  Pick one task: one WIP, one case, one explain slice, one promotion.

5. HOW TO TALK TO THE AGENT
==========================================================================
  Default agent behavior here: chat first. It answers and drafts in thread
  unless you say to write files.

  Phrases that work well:
    "explain [topic]"              Read-only; no file edits.
    "map cross-refs for [X]"       Grep pass; usually chat output.
    "draft loose"                  Thread draft; optional put in later.
    "put in"                       Write to kit [name file if you care].
    "promote" / "case"             Triggers promotion skill + checklist.
    "grep only" / "slice"          Forces small reads.

  One primary file per task:
    cases OR applied OR theory OR wip -- not all four for one case insert.

  Explicit beats vague:
    Good: "put in theory Analyst Notes -- formation stress block"
    Weak: "fix the thing about stress"

  For framework txt edits agents should respect:
    108 char max line width, 2 blank lines max between blocks.

6. READING THE KIT YOURSELF [grep discipline]
==========================================================================
  Never scroll 10k-line files blind. Pattern:

    grep -n "NEURODIVERGENT COHERENCE TYPE" coherence_framework_v25_theory.txt
    sed -n '7040,7080p' coherence_framework_v25_theory.txt

  cf_grep.txt has file maps, topic slices, WIP jump recipes.
  After big edits that move sections >~50 lines:

    scripts/refresh-cf-grep.sh

  Case lookup:
    grep -n "^\[CASE:NAME\]" coherence_framework_v25_cases.txt
    grep -n "REF:NAME" coherence_framework_v25_cases.txt

7. NEW CHAT DISCIPLINE [important for cost + quality]
==========================================================================
  Per chat: one topic or one bounded action. Multiple steps within that
  scope are OK [e.g. batch-migrate one WIP cluster]. Unrelated queue
  items = new chat.

  Context budget [usage meter %]:
    <50%: full scope for current topic/action [promotions, multi-file,
      batch within scope].
    ≥50%: **new chat recommended** for the next topic/action.
    ~100%: mandatory fresh chat [hard trigger].

  One thing per user message:
    Each send = one WIP, one case, one promote, or one bounded question.
    Agent executes one if you bundle unrelated items; split for the rest.

  Start a new chat when:
    - Bounded action done [WIP closed, cluster migrated, case written]
    - Switching file role [wip -> theory, cases -> applied]
    - Switching WIP number or unrelated queue item
    - Chat feels long [15+ turns] or answers go vague / repetitive
    - Context ≥50% [recommend new chat] or nears 100% [mandatory]
    - Section One theory work [high integration cost]

  Stay in same chat when:
    - Same topic or action until closed or parked
    - Multiple steps within that scope [batch edits on one migration pass]
    - Follow-ups on the same slice [typo, cross-ref, next paragraph]

  Agent may end with:
    NEW CHAT RECOMMENDED: [reason]. Next: [one queue line].

  New chats are free; long chats re-send history every turn.

10. TROUBLESHOOTING
==========================================================================
  Agent loads whole theory file
    -> Say "grep/sed slice only per cf_grep". Hook should nudge on cat.

  Agent edits too many files
    -> Say "one primary file only" or "chat first".

  cf_grep line numbers wrong
    -> Run scripts/refresh-cf-grep.sh after structural moves.

  Rules not applying
    -> Confirm workspace root is Framework folder; open a matching txt file.

  Hooks silent
    -> Hooks need bash + python3; session-start runs on new agent session.

  Commits / PRs
    -> Ask explicitly; agents default to no git write.
